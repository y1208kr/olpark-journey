# 분석 코드: 올팍 두 여정 진단

이 폴더의 파이썬 코드는 웹 페이지와 기획서에 나오는 분석 수치를 모두 다시 계산합니다.
수치는 사람이 입력하지 않았고, 스크립트를 실행한 결과 파일(figures/*_result.json)에서 가져왔습니다.

## 실행 방법

```
pip install -r requirements.txt
python run_all.py
```

한글 그림을 그리려면 한글 글꼴이 필요합니다. `_style.py`는 Noto Sans KR, 나눔고딕, 맑은 고딕, 애플 SD 고딕 순서로 글꼴을 찾습니다.

## 입력 자료

| 파일 | 내용 | 출처 |
|---|---|---|

| data/faq_text.tsv | 자주 묻는 질문 49문항의 번호, 제목, 답변 원문 | 공공데이터포털 15089962 한국체육산업개발 자주 묻는 질문정보 |
| ../data/faq_coded.csv | 문항별 고객 여정 단계 코딩 | 연구자 코딩(올림픽공원 37문항) |
| ../data/aggregates.json | 공연 일자, 평일과 주말의 시간대별 합계 | 공공데이터포털 15149169 공연정보, 15138735 |

자료를 옮길 때 원문과 같은지 확인하였습니다. FAQ 49문항은 문항마다 제목과 본문의 해시값을 브라우저 원본과 대조하였고 49문항 모두 일치하였습니다. 일별 시간대 자료는 평일 23일과 주말 8일의 합계가 집계 자료와 같은지 `03_corr_regression.py` 안에서 매번 검사합니다.

## 분석 목적과 방법

| 스크립트 | 묻는 질문 | 방법 | 그림 |
|---|---|---|---|
| 01_text_tfidf_network.py | 방문객은 여정 단계마다 어떤 단어로 질문하는가. 여러 단계에 걸쳐 함께 묻는 주제는 무엇인가 | 형태소 분석(kiwipiepy 명사), 단계별 TF-IDF, 워드클라우드, 동시출현 네트워크(연결 중심성, 매개 중심성, 모듈성 군집) | 01a, 01b, 01c |
| 02_kmeans_dayprofiles.py | 공원의 하루는 출차 시간 기준으로 몇 가지 유형으로 운영되는가. 공연일은 별도 유형인가 | 24시간 출차 비율의 k-means, 실루엣 계수로 k 선택 | 02a, 02b |
| 03_corr_regression.py | 21시 이후 출차는 공연일, 주말, 하루 입차량과 어떤 관계를 보이는가 | 피어슨, 스피어만 상관, OLS(HC3 표준오차), 공연일 하나씩 제외한 재추정 | 03a, 03b |

## 주요 결과와 해석 범위

1. 동시출현 네트워크에서 매개 중심성이 가장 높은 단어는 "시간"(0.202)이고, "시간"은 5개 여정 단계의 문항에 나왔습니다. 방문객의 질문은 여러 단계에서 운영 시간과 관련됩니다.
2. 출차 패턴은 실루엣 계수 기준으로 3개 유형(평일 23일, 토요일 중심 5일, 일요일 3일)으로 묶였습니다. 다만 k=2~5의 실루엣 계수 차이는 0.02 이내이므로 3개 유형은 여러 가능한 구분 중 하나입니다.
3. 공연일 3일은 별도 유형으로 묶이지 않았습니다. 7월 12일과 20일은 21시 이후 출차가 각각 1,363대, 1,509대로 월 중앙값 696대의 1.96배, 2.17배였습니다. 7월 1일은 720대로 중앙값과 비슷했습니다.
4. 회귀 분석에서 공연일 계수는 +541대였지만 유의하지 않았습니다(p = .122, n = 31). 공연일이 3일뿐이고 7월 1일의 값이 평소와 같아 신뢰구간이 넓습니다. 이 결과는 공연일과 늦은 출차의 상관을 보여 줄 뿐이며 인과를 뜻하지 않습니다.

## 적용하지 않은 방법과 이유

| 방법 | 적용하지 않은 이유 |
|---|---|
| BERTopic | 분석 대상 문서가 37문항이고 대부분 한두 문장입니다. BERTopic은 문서 임베딩을 군집화하므로 문서 수가 적으면 주제가 안정적으로 만들어지지 않습니다. 이 자료에는 TF-IDF와 동시출현 네트워크가 맞습니다. |
| 구조방정식(SEM) | 잠재 변수를 측정하는 설문 문항이 없고, 관측치도 31일뿐입니다. 측정 모형을 세울 자료가 없습니다. |
| 퍼지셋 질적비교분석(fsQCA) | 사례별 조건과 결과를 보정(calibration)할 근거 자료가 없습니다. 공원 여러 곳이나 여러 기간의 사례가 모이면 적용할 수 있습니다. |

## 이전 수치와 달라진 점

이전 초안은 브라우저에서 따로 계산한 늦은 출차 값(7월 12일 1,504대, 7월 20일 1,540대, 중앙값 721대)을 썼습니다. 그 값의 계산 정의를 코드로 다시 확인할 수 없어서, 이 폴더의 정의(그날 21시 00분부터 23시 59분 사이 출차 대수)로 다시 계산한 값으로 바꾸었습니다.
